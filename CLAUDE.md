Интернет-магазин чая «Чайный Мастер»: https://tea-master-team.ru
Репозиторий: https://github.com/Mark2803/TeaMarketV2 (основная ветка `main`).
Владелец — Марк. Общение и комментарии в коде — на русском. Объяснять простыми словами, без жаргона: Марк не программист.

## Стек

- **backend/** — Node.js 22, Express 5, TypeScript (ESM, `NodeNext`), Prisma 7 + адаптер `pg`, PostgreSQL 17, Zod 4.
- **frontend/** — React 19, Vite, React Router 7, TanStack Query, Zustand. Витрина и админка в одном приложении.
- **database/** — исходные SQL-миграции (001–140). Более новые миграции лежат в `backend/src/database/migrations/` (130–350).
- **docs-site/** — автогенерация документации (MkDocs + dependency-cruiser + mermaid).
- **docker-compose.yml** — только локальный PostgreSQL для разработки.

## Команды

backend:
- `npm run dev` — запуск в режиме разработки
- `npm run build` — сборка (сначала `prisma generate`, потом `tsc`)
- `npm start` — запуск собранного сервера (`dist/server.js`)
- `npm run typecheck` — проверка типов
- `npm run env:check` — полная проверка готовности сервера: настройки .env, база, ЮKassa, Яндекс Доставка, почта, хранилище изображений, Telegram (ничего не меняет и не отправляет)

frontend:
- `npm run dev`
- `npm run build`
- `npm run lint`

## Важные правила

1. **Сгенерированный клиент Prisma не хранится в git.** Папка `backend/src/generated/prisma` создаётся командой `prisma generate`, которая встроена в `build`, `dev` и `typecheck`. После изменения `backend/prisma/schema.prisma` ничего вручную генерировать не нужно — достаточно пересобрать.
2. **`node_modules` и `.env` не коммитим.** Все переменные окружения описаны в `backend/.env.example` и `frontend/.env.example`; при добавлении новой переменной — дописать её туда.
3. **Оплата — только автоматически через ЮKassa.** Заказ становится оплаченным только после того, как сервер перепроверил платёж у ЮKassa (`modules/orders/yookassa.service.ts`). Ручной смены статуса оплаты в админке нет и не должно быть (решение Марка).
4. **Работаем только с Яндекс Доставкой и ЮKassa** (решение Марка). Других служб доставки (СДЭК, 5Post, Ozon и т. п.) и других платёжных систем нет и не добавлять. Яндекс Доставка — один способ доставки с двумя режимами: до ПВЗ и до двери; стоимость всегда считает API Яндекса (`delivery-methods.service.ts` → `isYandexDeliveryMethod`), сервер отклоняет любые другие способы.
5. **Доставка — автоматически через Яндекс Доставку.** После подтверждённой оплаты отправление создаётся автоматически (`modules/moderator/yandex-shipments.service.ts`), статусы синхронизируются фоном. Ручной смены статуса доставки нет (решение Марка).
6. **Вебхук ЮKassa** доступен по двум адресам (`/api/payments/yookassa/webhook` и `/api/orders/yookassa/webhook`), оба обслуживает один обработчик `yookassa-webhook.controller.ts`. Данным из вебхука не доверяем — всегда перезапрашиваем платёж у ЮKassa.
7. **Безопасность админки:** сессия в подписанной cookie `tea_admin_session`, CSRF-токен для изменяющих запросов, ограничение частоты попыток входа. Разрешённые домены и чтение cookie — в `backend/src/config/http.ts` (одно место, не дублировать).
8. **Ошибки API:** для ожидаемых ошибок клиента бросать `HttpError(status, code, message)` из `middleware/error-handler.ts`. Ответ об ошибке всегда в формате `{ error: { code, message } }`, сообщение — на русском, понятное покупателю.
9. **Вход по телефону** в production отключён (нет SMS-провайдера); вход покупателей — по коду на email.
10. **Проверка настроек при запуске** (`backend/src/config/env-check.ts`): в production сервер не запускается, если не хватает обязательных настроек (база, админка, адрес сайта, ЮKassa, Яндекс Доставка, почта, хранилище изображений). Telegram и прочее — необязательно, только предупреждение. Новую обязательную переменную добавлять туда же.
11. **Транзакция оформления заказа** ждёт до 30 с, потому что внутри неё идёт расчёт стоимости Яндекс Доставки.

## Порядок работы

- Новые изменения — в отдельной ветке, не напрямую в `main`.
- Перед коммитом: `npm run typecheck` и `npm run build` в изменённой части (backend/frontend).
- Деньги, оплата, остатки и доставка — самые чувствительные места: любые изменения там проверять особенно тщательно и описывать Марку простыми словами.

Для сборки нужен `.env` с `DATABASE_URL` (на сервере он есть). `--include=dev` обязателен: если в терминале задано `NODE_ENV=production`, обычный `npm ci` не ставит TypeScript и Vite, и сборка падает. Не загружать `.env` в терминал через `set -a; . ./.env` перед сборкой.
